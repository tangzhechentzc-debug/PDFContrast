# 报表对比 · Excel / PDF / OCR

工程造价 PDF 现支持 D.1/D.2/D.3 汇总及 E.1 清单的“业务数据”比较：工程量、单价、金额等按数值比较，编码保留前导零，点击变化定位两侧原页；提取或匹配不确定时单列待核对。使用方法、规则及范围见 [造价报表业务比较](docs/cost-report-comparison.md)。

本地导入两份 `.xlsx` 或两份 `.pdf`。Excel 按工作表范围和业务键比较；PDF 先对应完整业务报表，再分别比较内容、结构、格式和版式，点击差异定位两侧原页。前端使用 React + Vite，后端使用 FastAPI、openpyxl、pdfplumber 和 Decimal；扫描页通过本机 RapidOCR / ONNX Runtime 执行 Paddle OCR 模型。原文件不修改，数据存放在本机。

## 使用

1. 选择旧版与新版文件，两侧必须同为 `.xlsx` 或同为 `.pdf`。可先下载界面提供的 Excel、文本 PDF 或扫描 PDF 示例。文件上传期间保持页面打开；上传完成后转为后台读取，界面显示当前旧/新版文件、处理阶段、第几页/总页数与已处理页数。此时刷新可恢复同一任务，不会重新上传。Excel显示工作表数量与名称。
2. PDF 确认完整报表的对应关系：封面、扉页、说明和空白表单同样参与；模板与填写版可对应，工程名称、日期、表头和方向差别作为结果报告。重复类型或缺少编号时核对候选并填写人工配对依据。Excel 则确认工作表、表头起止行、范围和对应列，再选择唯一业务键或固定位置模式。
3. 执行比较。搜索项目或筛选差异类型，点击差异后左右分别定位原工作表地址或 PDF 页码与区域。新 PDF 按每张报表展示四类摘要，支持共同比例的并排、切换和叠加；只有版式变化也明确记为差异。没有内容差异时也能浏览完整原件。OCR 结果包括同值内容在内初始均待核验；可进入“校正与核验 OCR”对照原图处理。
4. 扫描内容可进入“校正与核验 OCR”：选择版本、页面和识别格，填写校正文本与原因后保存；再独立确认单格或整页。整页核验需确认没有漏字、漏行、错列。校正会撤销相应识别格和页面的核验状态。
5. 遇到漏行、错列时，进入“补行与调整结构”。选择物理表或文字区域，插入行列、调整顺序、交换错位格或移动到空格，再填写原因并确认行列结构。已有格保持原文定位，人工补录格仅定位整页；文字区域也可重建成表格。保存后本页内容核验失效，需要重新核验。
6. 文字校正可按原配置重新比较；行列或表头调整后，先加载最新配置。新 PDF 核对完整报表对应关系，旧版本和 Excel 核对范围、列映射及业务键后再比较。历史结果可重新打开；导出包含当次修订范围内的文字/核验记录和逐格结构修改前后明细。刷新可恢复当前任务和结果；保留地址中的任务/结果参数可再次打开。

应用没有桌面 Excel 自动跳转：定位发生在应用的只读原工作表视图中，行列号对应原文件。视图显示相邻区域，不是 Excel 打印页面的像素级复刻。

PDF 查看器显示原文件页面的本地渲染图像，高亮是独立覆盖层，不会写回 PDF。两侧按同一物理比例显示，保留原始纸张尺寸、横竖方向和空白范围；查看器缩放不参与文件比较。完整对象覆盖标题、工程名称、正文、表框、填写线、签章说明、注释及页眉页脚。同类型多实例按对象、章节和顺序区分；匹配或提取不确定时单列待确认，不能将报表清单核对等同于内容比较完成。

## PDF 与 OCR

- 文本页由 pdfplumber 提取表格和文字来源框；包含扫描正文的页面进入 OCR，不能仅因存在文本页眉就跳过识别。
- 保留可靠原生文字与表格，仅对图像、乱码或未覆盖的可见内容区域执行 OCR，按原页坐标合并和去重。原生格与 OCR 格分别保留来源；图片标志或水印不再导致整页原生文字被替换。
- OCR 模型随 `rapidocr-onnxruntime` 包安装，在本机运行，不上传文档或调用云端识别。安装依赖需要网络，安装后处理文件不需要网络模型服务。
- 规则网格表结合线条几何与 OCR 文字框重建；无法可靠恢复结构时保留文字区域并提示限制。OCR 误识别、漏行、错列仍需核对原图。
- 版本 2 按编号、标题和上下文对应完整业务报表，不以工程名、已填写状态、表头或方向一致作为前提。文字、结构、格式和版式分别比较并记录验证范围；空表框或没有规则网格不是提取失败。提取失败既不能证明缺失，也不能证明一致。
- 原生 PDF 保存文字与矢量绘制属性、原始物理尺寸和统一渲染证据；字体比较忽略子集前缀。段落有效行距通过原生基线测量，左／中／右对齐依据可证文字边缘或单元格参考；不确定范围逐项保留，导出包含段落测量证据。正文和空白表单不必转成数据表。兼容、可靠的网格仍按业务键和 Decimal 比较字段，行重排不冒充内容增删；行列排列和位置变化另由结构、版式比较报告。
- 人工校正和核验追加保存到 SQLite，保留原始识别文本、修改前后值、原因和时间；不会覆盖 PDF、原页图像或提取 JSON。结构调整支持补行、增删/重排行列和格交换/移动，保留调整前后矩阵与稳定身份。旧版本中结构不明的页需按原图重建确认后再核验内容；版本 2 的说明页可以独立核验 OCR 文字，不必先重建为网格。提取失败且没有可编辑区域的页仍保留失败状态；这不会确认未知字体或行列结构。当前没有手动框选重识别。扫描字体名、原编辑器的段落设置、复杂无框表、倾斜/低清扫描内容等不能可靠确定时继续列为未验证；视觉变化不等于确定其具体字体属性。

## Excel 比较规则

- 同模板或可配置列映射的表格，支持多行/合并表头；一个工作表含多张报表时可分配不同范围。
- 按业务键比较，行重排不记作内容变化。重复键、空键等不能唯一匹配的情况显示待核对。
- 数字按 Decimal 比较，默认绝对容差为 0；显示格式不会把 `1.231 → 1.234` 舍入为相同。编号保留字符串及前导零，空值不等于零。
- 单独显示值、公式及可选格式差异；按业务键或固定位置对齐表格并比较全部单元格，结果全量保存并分页显示。
- 公式值来自 Excel 文件已有缓存，不在本工具内重新计算；缺缓存明确列为结果不可用。
- 未比较工作表/范围和解析限制在覆盖提示中展示。不能将部分比较当作整份文件一致。

## 首版边界

接收 `.xlsx` 与 `.pdf`；不支持 PDF 与 Excel 混合比较、旧式 `.xls`、含宏 `.xlsm`。PDF 图形与签章区域可保留视觉变化证据，但不判断签章真实性、图表业务含义或未提取到的编辑软件属性。加密文件需先提供可读取的副本。每份最多 50 MB；Excel 解压后最多 200 MB、单表矩形区域 500,000 格、每份最多 100,000 非空格。PDF 不再按整册页数、累计渲染像素或整册单元格数截断；单页渲染仍最多约 1200 万像素，单页提取最多 100,000 格。超过 100 页或预渲染预算时，完整外观证据逐页压缩存盘，比较时按报表读取并释放，原页 PNG 按需生成并缓存。一次最多配置 5000 组比较范围，关闭的配对卡不加载编辑控件。整册仍需足够的内存、磁盘和处理时间；这不代表已完成任意大文件或大型扫描册压测。

原文件副本、提取结果、PDF 原页渲染和 SQLite 任务保存在本地。源码启动默认使用项目 `.data/`，Windows 安装版默认使用 `%LOCALAPPDATA%\ReportContrast`。两种方式都可用 `REPORTCONTRAST_DATA_DIR` 指定目录。保留目录可恢复任务；没有实现自动清理。

完整报表四类比较、页面对应和属性验证范围见 `docs/pdf-full-report-contract.md`。旧版本 1 的业务报表清单行为仍记录于 `docs/pdf-business-inventory-contract.md`，仅供旧数据与历史运行。重新处理会复制原件并创建独立任务，保留父任务链接；旧任务的人工修订和结果不改写，新区域不自动套用旧坐标修订。
