# 报表对比工具：产品与技术设计

版本：0.1 · 日期：2026-11-04 · 状态：设计稿，尚未实现比较引擎。

## 1. 交付目标与已确认范围

用户需要对比两份 PDF 或两份 Excel，查看差异明细，并从差异定位到原文件。PDF 同时包含软件导出的文本页和扫描页，二者都纳入首版。核心采用 openpyxl、pdfplumber、DataComPy；扫描件增加本地 PaddleOCR 表格识别能力。

产品形态采用本地 Web 工具：本机服务处理文件，浏览器提供双栏查看器。此形态是本次设计假设，并非用户已指定的平台。首版不需要账号、云存储或外部大模型。模型和软件依赖在安装阶段准备好，比较过程可离线进行。尚无真实报表样例，提取质量、速度、目标机器 OCR 部署情况均未实测。

最终体验：导入旧版与新版 → 检查识别范围和匹配关系 → 执行比较 → 筛选差异 → 点击差异并查看两侧原文。比较结果必须同时回答“哪里变了”和“哪些内容尚未可靠比较”。

### 首版范围

| 项目 | 支持范围与边界 |
| --- | --- |
| PDF | 两份 PDF；文本页、扫描页、混合页；表格数据和已选区域内文字；扫描结果允许人工校正 |
| Excel | 两份 .xlsx；工作表、表格范围、数值、文本、公式、已存缓存值；常用格式变化可选择比较 |
| 比较方式 | 业务键对齐优先；无可靠键时由用户明确选择固定位置比较 |
| 定位 | PDF 原始页面覆盖高亮；Excel 原工作表地址与只读单元格视图 |
| 输出 | 全量差异明细、待核对清单、比较范围和规则；可导出独立 XLSX 报告 |
| 不含 | PDF 与 Excel 混合比较、.xls/.xlsb/.xlsm、批量文件配对、自动修改原文件、Excel 公式重算、桌面 Excel 跳转适配、图表/签章/图片视觉像素比较 |

“Excel 原工作表视图”保留行列位置及常见样式，不承诺与 Excel 打印页面完全一致。PDF 页面能够原样显示，但图形变化不属于首版数据比较范围。结果标题明确写“所选报表内容对比”，不宣称覆盖文件全部对象。

## 2. 用户任务与设计原则

主要使用者是核对报表版本的业务人员。已知需求来自本次会话，没有访谈数据或现有耗时基线，不能虚构效率提升比例。

- 按业务项目匹配：一行移动到另一页，不应被当作金额修改。
- 差异可追溯：保留两侧独立来源、原值、标准化值和判定规则。
- 不确定性可见：识别失败、重复主键、无公式缓存均不能被隐藏为“相同”。
- 原件只读：识别校正写入任务的校正记录，导出写入新文件。
- 分类统计：行增删、字段修改、公式变化、待核对分别计数；不给出跨字段相加的“总差额”。

## 3. 页面与操作流程

### 3.1 创建比较

两个文件区域标明“旧版”和“新版”，支持选择、拖入和交换。校验真实文件类型与扩展名，两侧必须同类型。显示文件名、大小、PDF 页数或 Excel 工作表数。

按钮为“识别报表”。非法文件、加密文件、损坏文件在此给出明确原因。首版遇到加密文件提示提供可读取副本，不采集或保存文档密码。

初始工程限制建议每份 50 MB、PDF 200 页、Excel 每个选择区域 100,000 个非空单元格；这些是待样本压测调整的产品限制，不是库性能声明。另设解压体积和像素预算，超限时提示缩小范围。

### 3.2 识别与配对

左边是页面或工作表目录，中间是识别预览，右边是规则。系统建议表格配对；用户可在同一页确认多张表和跨页续表。

PDF 按页/区域分类，不用“有几个字符”就认定整页是文本型：带文本页眉的扫描正文仍需要 OCR。对于可用文本和扫描区域重叠，优先保留可核对文本结果，去除重复识别；乱码、空表、缺列、疑似错列进入核对列表。

提供四种必要修正：框选比较区域、指定表头行、调整表格/列映射、选择复合业务键。多级表头表示为路径，例如“本期/收入/金额”。自动去除重复页眉只影响标准化表，原件与来源不变。

规则默认：比较内容及 Excel 公式；格式比较关闭；前后空白可忽略；编号按字符串；空白不等于零；金额绝对容差 0、相对容差 0；单位不明则待确认。允许按列配置容差、单位换算和字段类型，并在执行前显示规则摘要。

对于扫描页，显示识别方式和需要核对的单元格，允许从原图校正。校正只写入 overlay（原始识别值、校正值、原因、时间），保留原始识别证据。高置信度不是正确性的保证；未人工核对的 OCR 内容保留“识别结果待核验”标识。

对于 OCR 错切行列、合并格结构错误，提供“重新框选子表并识别”和“将此区域标为未比较”两个首版出口。文本校正不承诺修复结构问题；重新识别生成独立提取版本及新的来源框，原版本保留。仍无法正确识别时保持未比较状态，不强行形成有效表格。

已确定的部分可以先比较；用户忽略的表/页面必须进入覆盖范围摘要。不能通过“继续”按钮让未知区域消失。

### 3.3 对比工作台

桌面布局：顶栏显示任务、两侧文件和比较范围；主体左侧是差异目录，中间两栏为旧/新原文；底部或可展开侧栏显示选中差异详情。

```text
旧版名称 → 新版名称       所选范围：已比较 / 待核对 / 已排除       导出明细
┌────────────────┬──────────────────────┬──────────────────────┐
│ 查找项目/字段  │ 旧版 · 页码/单元格    │ 新版 · 页码/单元格    │
│ 类型/表名筛选  │                      │                      │
│                │ 原文或单元格视图     │ 原文或单元格视图     │
│ 金额变化 A001  │    [定位高亮]        │    [定位高亮]        │
│ 新增项目 A004  │                      │                      │
│ 待核对 A003    │                      │                      │
├────────────────┴──────────────────────┴──────────────────────┤
│ 项目、字段、旧值、新值、差额、证据来源、判定规则、核对状态    │
└─────────────────────────────────────────────────────────────┘
```

差异明细可按类型、报表、字段、核对状态筛选，可搜索项目名称/编号。支持上一条/下一条及键盘操作。筛选后选中项不在结果中时自动选择第一条，空结果明确显示，无残留高亮。

PDF 点击差异后，两侧各跳转自身页码并滚到目标区域；不要求旧版第 3 页对应新版第 3 页。支持缩放、旋转、原始页码输入。默认只联动选中项，不强制按滚动百分比同步。跨页来源有“上一处/下一处证据”。

Excel 点击差异后，两侧切换自身工作表并滚动到各自地址；显示行号、列字母、合并区域、公式栏及原始值。隐藏行列/工作表出现目标时以提示方式展开。可复制“工作表!地址”，下载所选原文件副本；浏览器不承诺启动桌面 Excel 并定位。

新增/删除只高亮存在的一侧。只有对应范围的提取完整性、结构及匹配均已确认，另一侧才显示“本版本无此项目”；扫描识别不完整或尚未核验时显示“疑似新增/删除，请核对对侧原图”，并提供对应范围入口。无法匹配显示双方候选，不能伪造确定对应关系。

底部详情同时展示：原始读值/识别文本、规范化值、公式及缓存值（如适用）、差额、单位、规则、提取方式、两侧位置。差额定义为新版减旧版；仅对单位相容且值可靠的数字计算。旧值为 0 时变化率为空，不输出无穷大。

### 3.4 结果措辞与状态

| 情况 | 显示措辞 |
| --- | --- |
| 范围内全部可比较且无差异、没有未核验 OCR | 所选范围未发现差异 |
| 存在明确差异 | 发现内容差异，附分类计数 |
| OCR 识别值相同但尚未复核 | 按识别结果未发现差异，扫描内容待核验 |
| OCR 识别值不同但尚未复核 | 疑似差异，需核对原图 |
| 部分页面失败/匹配有歧义 | 部分完成；显示未比较范围 |
| 选择范围未提取到可比较内容 | 无法完成比较；不显示“无差异” |

行/列新增删除各记一个结构事件，支持展开其字段，不同时把每个字段计入修改总数。字段修改可包含内容、公式、格式多个维度，事件 ID 不同；UI 显示“字段变化数”和“受影响项目数”，不混为同一个数量。

## 4. 技术结构

```text
浏览器：React + TypeScript
  差异列表 / 规则与配对 / PDF.js / Excel 只读虚拟网格
               │ 本机 HTTP API
FastAPI：任务状态 / 文件与规则 / 差异查询 / 来源定位 / 导出
               │ 本机工作进程（耗时任务不占请求线程）
               ├─ Excel → openpyxl → 表格+公式+缓存+来源
               └─ PDF → pdfplumber → 文本与表格+来源
                          └─ 扫描区域 → 页面渲染 → PaddleOCR → 表格+文字框
               ↓
       校正与范围 → 标准化 → 表/列/行匹配
               ↓
       DataComPy + Decimal 数值规则 → 全量 DiffItem
               ↓
       SQLite（索引和任务）+ 本地文件目录（原件副本和提取产物）
```

PDF 渲染后端建议 pypdfium2；OCR 采用 PaddleOCR 的 PP-StructureV3 管线进行表格结构与文本提取。它们是拟选依赖，应先验证目标 Mac/Windows 的运行包及模型组合。使用固定本地模型路径，不调用云端 OCR；必要的模型下载在安装阶段显式完成。OCR 适配器隔离环境依赖，首版不引入分布式队列。

| 模块 | 责任 |
| --- | --- |
| ingestion | 文件真实类型、原始副本、SHA-256、大小/解析预算 |
| extractors/excel | 工作表与区域、值/公式/缓存/常用格式、原始地址 |
| extractors/pdf | 文本层质量、表格单元格框、区域分类与跨页片段 |
| extractors/ocr | 图像与预处理变换、OCR 框、表结构、原始质量证据 |
| normalization | 类型、表头路径、单位、空值、校正记录应用 |
| matching | 表/字段映射、业务键验证、一对一行匹配、歧义列表 |
| comparison | DataComPy 适配、Decimal 规则、公式/格式差异、事件生成 |
| provenance | 原文件坐标协议、Excel 区域读取、PDF 高亮变换 |
| jobs/export | 状态、失败恢复、分页明细、报告和规则快照 |

只实现这些直接服务当前功能的模块；不额外设计插件市场、多租户、审批流。

## 5. 统一数据与差异模型

### 5.1 原文引用 SourceRef

每个解析单元格一开始就携带来源；后续排序、合并、匹配均保留引用。来源列不加入 DataComPy 的业务比较字段。

ExcelSourceRef：`file_id, sheet_name, cell_address, merged_range?`。合并格取锚点值，视图高亮整个合并范围；继承分类标题时指向真实标题锚点。

PdfSourceRef：`file_id, page_index, quads[], coordinate_space, media_box, crop_box, rotation, user_unit, extraction_method`。API 的 page_index 为 0 起始，界面页码为 1 起始。一个逻辑单元格可以对应多页多个 SourceRef。

坐标约定为未旋转的 PDF 默认用户空间；保存实际页面几何信息及变换，避免默认每页从 (0,0) 开始。pdfplumber 的 top-origin bbox 转换由适配器负责；OCR 图像坐标通过渲染变换和预处理的逆变换映射回同一空间。首版避免没有可逆映射的非线性去畸变。

前端以 PDF.js 当前 viewport 变换每个四边形顶点再叠加高亮。原页面旋转只应用一次，用户额外旋转由 viewport 统一处理。canvas 高分辨率倍率不用于 CSS 高亮坐标。验证 0/90/180/270 度、裁剪框偏移、非默认 userUnit、缩放和不同 DPR。

### 5.2 逻辑单元格与表

Cell：`cell_id, raw_value, raw_text?, normalized_value, value_type, unit, formula?, cached_value?, cache_status, number_format?, style_signature?, source_refs[], extraction_quality, correction_id?`。

Table：`table_id, title, header_paths, group_path, rows, source_regions[], extraction_method, mapping_status`。原始表结构与规范化表分开保存。逻辑行包含业务键、来源和稳定 ID，不能用当前排序下的序号作为业务身份。

### 5.3 差异 DiffItem

```json
{
  "id": "diff-001",
  "run_id": "run-001",
  "table_pair_id": "pair-001",
  "kind": "value_changed",
  "row_key": {"项目编码": "A001"},
  "field_path": ["本期", "金额"],
  "old": {"raw": "12,000.00", "normalized": "12000.00", "source_ids": ["s-old-1"]},
  "new": {"raw": "12,800.00", "normalized": "12800.00", "source_ids": ["s-new-1"]},
  "delta": "800.00",
  "unit": "元",
  "evidence_status": "native_text",
  "review_status": "unreviewed",
  "rule_id": "amount-exact",
  "reason": "金额绝对容差为 0；新版减旧版为 800.00"
}
```

kind 包括表/行/列增删、value_changed、formula_changed、format_changed、text_changed、match_ambiguous、extraction_uncertain、formula_result_unavailable。无一侧来源时对应 old/new 为 null。疑似差异、识别待核验和匹配歧义与确定差异分组显示。

识别/匹配证据状态与用户复核状态独立：标记“已查看”不等于确认 OCR 正确。只有显式“与原图核对一致”或校正后重跑，才解除对应识别待核验状态；文本型机器结果也不声称人工复核。

独立 CellReview 记录 `extraction_version, cell_id, correction_version, status, reviewed_at`，RangeReview 记录相应原文区域的结构与完整性核验。两者不依赖是否存在 DiffItem，因此识别值相同的内容也能核验。明确逐项核验或选定范围核验后更新核验统计；批量核验必须由用户主动提交。提取版本/校正变更会使受影响核验失效，不能沿用旧批准。核验状态作为同一 run 的独立 review_revision 更新，导出保存该版本；值或结构变更必须新建 run。

### 5.4 范围和可复现性

任务记录输入文件哈希、库/模型版本、配置版本、表格映射、业务键、所选/排除范围、校正版本。每次修改规则或识别校正产生新 run_id，旧结果标为历史，不把旧缓存显示为新结果。

Coverage 记录左右各自的页/区域/工作表：已处理、提取失败、待匹配、待核验、明确排除。统计“单元格、记录、页面”分别给出分母，不能用混合单位生成百分比；不设置没有定义分母的准确率或覆盖率。

## 6. 提取、匹配与比较规则

### Excel

同一原文件分别以 data_only=False 和 True 读取，按工作表/地址合并。openpyxl 不执行公式；缓存缺失表示“结果不可用”，不能当空白。缓存存在仍注明“文件保存结果，未重算”。数组/数据表公式需要记录作用范围，不能只比较左上格后声称全范围已计算验证。[1][2]

默认纳入隐藏行列与工作表，在范围页可明确排除。表格区之外的非空单元格也必须列出为待纳入范围，不能悄悄丢弃标题、备注。样式按字体/填充/边框/对齐/数字格式的语义属性比较，不用工作簿内部 style_id 判断相同。

### PDF 与扫描页

文本型 PDF 使用 find_tables() 获取结构和单元格坐标，再读取内容，避免只提取丢失来源的字符串矩阵。表格外文字区单独匹配与比较；首版按经确认的块配对做文本 diff，复杂重排提示确认。[3]

跨页续表先按表头路径、标题及列结构提出候选；合并结果保存每个片段位置。无法确认的续表不自动拼接。OCR 保存文字置信度、结构异常、映射状态；不把单一置信度阈值称为准确率。阈值需要真实样本校准。

初版扫描处理以可逆旋转、裁切、缩放为主。文字识别和表格结构识别共同使用；不能只按 OCR 文字行拼出表格而忽略错列。即使高置信度，未复核 OCR 相同项仍可从“扫描内容核验”入口访问，防止两边同样误识别后被隐藏。

### 匹配

先表，再列，再行。表按标题/表头结构给候选；字段映射尽量用完整表头路径；行键优先“分组路径＋项目编号＋期间”。键须两侧各自唯一且非空。

重复键先匹配组内完全相同记录（保留多重集合数量），剩余无法唯一配对的部分进入待确认，支持补充键或手工一对一配对。同名小计借助分组路径区分。未完成配对时不利用 DataComPy 的重复行序号配对生成确定差异。[4]

在对应范围完整性已确认的前提下，主键变更默认表现为旧项目删除/新项目新增，可人工确认是同一项目后改为字段变化；扫描键值未核验时先视为匹配待确认。行顺序变化不记为内容差异；固定位置模式例外，并在报告中注明。

### 数值与 DataComPy

采用 DataComPy 1.x 的 PandasCompare 接口，锁定经过验证的具体版本。它负责已对齐表的共同/独有记录和字段差异；不负责 PDF 识别或业务实体推断。

金额/数量转 Decimal，JSON 用十进制字符串。openpyxl 已解析为 float 时使用 Decimal(str(value))，默认保留已有有效数字，不按 number_format 舍入。只有用户显式选择业务舍入规则才量化，并保存该规则；显示格式只影响显示。不声称恢复 Excel 未存储的精度，文件存储位级审计不在首版范围。

对受控数字列用自定义 comparator 接管，返回逐项布尔掩码，禁止这些列回退到 float 比较。规则默认 `abs(new-old) <= abs_tol`；金额 rel_tol=0。差额和变化率由 Decimal 计算。非法数值、缺值和公式错误为明确的类型/状态，不静默转换为 0。实现时用边界样本验证 DataComPy 适配。[5]

DataComPy 摘要用于核对计数；全量事件从共同及独有记录生成，不能把 report 中有限的样例行当明细。返回明细使用分页，导出遍历全部事件。[6]

单位换算必须来自表头、列配置或用户确认。百分比规范化为明确比例；编号保留前导零；日期按单元格类型和工作簿日期系统读取。展示格式变化与数值变化独立，1 与 1.00 的金额可相同，格式另报。

## 7. API 与任务状态

| 接口 | 用途 |
| --- | --- |
| POST /api/jobs | 上传两份文件并建立任务；返回文件 ID |
| POST /api/jobs/{id}/extract | 启动识别；返回 202 |
| GET /api/jobs/{id} | 阶段、已完成单位、告警与覆盖情况 |
| GET /api/jobs/{id}/tables | 识别表、表头、配对建议、键质量 |
| PUT /api/jobs/{id}/config | 保存映射、范围、规则，带配置版本 |
| POST /api/jobs/{id}/corrections | 保存识别校正与来源；不修改原件 |
| GET /api/jobs/{id}/cells | 按提取版本/区域分页枚举单元格，可筛选全部未核验 OCR 内容 |
| POST /api/jobs/{id}/reviews | 提交指定版本的单元格或区域核验，覆盖相同但无差异事件的内容 |
| POST /api/jobs/{id}/reextract | 重新框选区域识别，生成新提取版本并使相关核验失效 |
| POST /api/jobs/{id}/runs | 以配置/校正版本启动比较；返回 run_id |
| GET /api/runs/{id}/summary | 分类统计、扫描核验状态与范围摘要 |
| GET /api/runs/{id}/diffs | 按类型/表/关键字筛选，稳定游标分页 |
| GET /api/runs/{id}/diffs/{diff_id} | 两侧内容、规则及全部来源 |
| GET /api/sources/{source_id} | 定位信息；服务端验证任务归属 |
| GET /api/files/{file_id}/content | 原文件副本流，PDF 预览支持 Range |
| GET /api/files/{file_id}/sheet-region | 按工作表与区域返回单元格视图 |
| PATCH /api/runs/{id}/diffs/{diff_id}/review | 复核结果、理由与时间 |
| POST /api/runs/{id}/exports | 生成全量 XLSX 明细与范围/规则快照 |
| POST /api/jobs/{id}/cancel | 取消尚未完成的本机任务 |

状态：created → extracting → needs_review / ready → comparing → completed / completed_with_issues；任意执行阶段可 failed / cancelled。扫描未复核、部分解析失败或歧义未解决都进入 completed_with_issues。已有结果仍可查看，但不能用绿色“全部一致”。

失败返回明确阶段、受影响范围和可恢复操作。重试产生新执行记录；只复用哈希、解析版本、规则版本和校正版本一致的中间结果。OCR 工作进程可按页取消；主进程轮询进度，首版不需要 WebSocket。

## 8. 本地保存与导出

服务只绑定回环地址；浏览器只通过文件 ID 读取任务内副本，不提供任意路径读取。使用本机会话凭据与来源校验，文档内容在页面/导出中按文本处理，避免公式或 HTML 被执行。

任务目录保存 originals、extracted、corrections、runs、exports；SQLite 保存任务元数据和明细索引。原件副本写入后保持不变；预览不重新保存 Excel 原件。任务清理是显式操作，列出范围后确认，不删除用户源文件。

导出 XLSX 包含：摘要、全量差异、待核对、覆盖范围、规则。公式文本作为文本写入，防止报告执行公式。位置以页码或工作表/地址表示；导出文件不承诺离开本机任务后还能打开应用内定位链接。

## 10. 实施顺序与待验证项

1. 用人工标注样本固定统一模型、Decimal 规则与来源协议。
2. 完成 XLSX 解析、匹配、全量明细与单元格联动，验证最小闭环。
3. 加入文本 PDF 表格与文字区域，验证分页、旋转、坐标高亮。
4. 加入扫描/混合 PDF、本地 OCR、核验校正与覆盖范围展示。
5. 完成报告导出、取消重试及验收矩阵。四条输入路径都通过后才视为首版完成。

样本仍待提供：文本 PDF、扫描 PDF、混合 PDF、带合并表头/公式的 XLSX 各一对，最好包含已知差异。业务主键、允许容差、典型文件规模和目标操作系统尚无真实数据，本设计给出可配置机制，不预设其实际值。无样本不阻碍设计，但不能声称识别效果已验证。
