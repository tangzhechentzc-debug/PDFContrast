# PDF 业务报表清单与比较快照

本文记录版本 1 的行为，用于旧提取与历史运行。新 PDF 任务使用版本 2：完整报表配对不再要求工程对象、表头和填写值相同，详见 [完整业务报表比较](pdf-full-report-contract.md)。

新提取数据携带 `report_inventory_version: 1`。识别出的业务报表保存在 `reports`，物理提取区域仍保存在 `sheets`。类型、对象、页范围、标题证据与成员区域分别记录；物理区域数量不是报表数量。旧提取数据及旧运行不自动改写。

## 结果层级

PDF 比较结果可包含：

- `type_inventory`：`shared`、`old_only`、`new_only`、`uncertain` 四组报表类型，记录类型代码、标题及两侧物理页。
- `reports`：实例关系、两侧来源、依据、阻塞原因与内容比较状态。`presence` 为 `shared / old_only / new_only / uncertain`；`confirmation` 为 `confirmed / pending`；`content_status` 为 `reliable / pending / not_applicable`。类型共有不自动确认实例共有；未填写的模板对象不是任意工程的通配符。
- `issues`：提取、结构、身份和配对问题，包含影响报表、版本、页、来源与处理入口。
- `non_report_regions`：文档正文、空白页、报表续注及未确定文档区域，保留物理页与判定依据，不把这些区域直接计算为报表实例。
- 每条差异可带 `report_id` 和 `layer`（`completeness / content / uncertainty`）。整张报表单侧缺失使用报表层级事件，不展开为全表逐格删除。

这些字段随 run 保存。界面、筛选统计和导出读取同一个 run；旧 run 没有新字段时明确显示尚无业务完整性判定，不用最新提取结果补写旧结论。

`GET /api/runs/{run_id}/diffs` 增加可选 `report_id` 与 `layer` 参数。过滤在服务端计数与分页之前执行。`layer=all` 保留全部事件。

## 配对确认

`PairConfig` 增加 `pairing_confirmed`（默认 false）与 `confirmation_reason`。人工确认必须说明原文依据；它不等于确认 OCR 内容，也不能绕过明确的类型或工程对象冲突。没有可靠共有实例时允许提交空 `pairs`，生成完整性与待处理结果，不能因此声称内容一致。

重复或空业务键保留为匹配问题。单列文字块不充当可靠字段表。跨页拼接需要报表身份、表头及续页证据，不能仅因为表头相同就合并。

## 重新提取与历史

`POST /api/jobs/{job_id}/reprocess` 仅接受 PDF 任务，无请求体，返回 202 导入状态。服务端验证两份原件 SHA-256 后复制至新任务，复用后台导入进度；新任务记录 `parent_job_id`。

原 PDF、原提取 JSON、人工修订和历史运行保持不变。新提取区域可能改变，因此不自动迁移旧坐标上的人工修订。原任务可通过父任务链接访问。新任务的提取、核验和比较记录独立保存。

## 导出

在原有全部差异、待核对、范围规则及修订明细之外，新运行导出报表完整性、报表类型覆盖、提取与配对问题、可靠共有报表内容差异、非报表文档范围五张表。待确认缺失与已确认缺失分别标注。可靠内容表排除 `severity=issue`，原始事件仍保留在全部差异中。

## 保留边界

标题、对象和版式不清楚时保守列为待确认；自动识别不是业务认证。不同模板的字段语义、无框复杂表、缺失的清单实例标识仍可能需要人工确认。原生文字与区域 OCR 的来源分别保存，图形和签章视觉差异不在字段比较范围内。
